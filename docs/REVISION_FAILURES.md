# Subsystem Revision Guide: Failure Modes & Recovery Matrix

## 1. System Failure Modes & Recovery Matrix

| Scenario | Root Cause | Detection Mechanism | Immediate Pipeline Impact | Recovery Procedure | Safety & Idempotency Guarantee |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Upstream Emitter Delay / GCS Missing Files** | Network outage or batch producer lag; GCS bucket empty for scheduled hour. | Airflow task fails with `FileNotFound` or empty source objects warning. | Downstream dbt model runs for that hour are delayed; warehouse missing current hour data. | Airflow retries 2 times with exponential backoff (5 min delay). If still failing, alert fires; backfill script runs once producer catches up. | Staging partition is purged prior to insertion; no partial rows or duplicates created. |
| **2. BigQuery Slot Exhaustion / Query Timeout** | High concurrent query load or runaway ad-hoc analytics queries consuming warehouse slots. | Airflow task hits 30-minute `execution_timeout` and transitions to `FAILED`. | Current hourly run fails; downstream marts not refreshed. | Airflow automatically retries. If persistent, investigate slot allocation in GCP Console; rerunning DAG resumes from failed task. | Queries wrapped in atomic transactions; partial dbt table rebuilds are rolled back. |
| **3. Upstream Schema Drift (New Field Added)** | Mobile app team deploys new version with an added unannounced field. | `scripts/check_schema.py` or contract validation detects drift; dbt staging view compilation. | If additive (backward-compatible), BigQuery ignores or ingests as null. If breaking, CI / validator halts pipeline. | Update `contracts/{event}.yml`, add column to `dbt/models/staging/stg_*.sql`, run `./scripts/validate.sh`, deploy via PR. | Additive schema changes never break existing downstream facts or marts queries. |
| **4. Corrupted or Malformed Data Partition** | Producer emitted negative watch durations or corrupted JSON strings. | Tier 3 singular dbt tests (`assert_fact_streams_valid_duration.sql`) fail. | `dbt test` task fails; pipeline stops before marts or BI layer is updated. | Quarantine bad Parquet files in GCS; trigger `scripts/backfill.py` for target partition with sanitized data. | Marts never expose unvalidated or corrupted metrics to executive dashboards. |
| **5. Accidental Dropped Table in BigQuery** | Human operator or errant script drops `core.fact_ad_events`. | Alerting triggers; downstream queries return `404 Not Found`. | Dashboard reports fail to load. | Use BigQuery **Time Travel** (7-day window) to restore table instantaneously: `CREATE TABLE core.fact_ad_events AS SELECT * FROM core.fact_ad_events FOR SYSTEM_TIME AS OF ...` | Zero permanent data loss; restored state exactly matches point-in-time snapshot. |
| **6. Airflow Scheduler / Worker Crash** | Node OOM or Kubernetes pod eviction during DAG execution. | Health check probes fail; Airflow Webserver marks DAG run as `stalled`. | Pipeline execution paused. | Cloud Composer / Kubernetes auto-restarts pod; scheduler recovers DAG run state from metadata DB. | Tasks use idempotent partition replacement, allowing safe in-flight resumption. |
| **7. Broken SQL Transformation Deployed to Main** | Syntax error or invalid join logic slipped into a production release. | GitHub Actions CI or post-deployment `dbt test` fails. | New hourly runs fail during transformation phase. | Execute git rollback: `git revert HEAD` and push to trigger automated CI/CD redeploy. | Previous table materialization in BigQuery remains intact until a valid build completes. |
